## Architecture Decisions

1. **Single-instance**: Simpler for v1, can shard by market later
2. **In-memory state**: Rebuild from event log, snapshots every 5min
3. **Separate service**: CLOB runs as microservice, main API handles settlement

## Known Limitations (v1)

- No horizontal scaling (single instance)
- Order book state lost on restart (rebuilt from log)
- No complex order types (limit/market only)
